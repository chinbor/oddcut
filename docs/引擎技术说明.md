# oddcut 引擎技术说明

> 从 README 移过来的开发笔记（2026-10-18）。部分路径（如 `output/` 下的成片）只存在于开发者本机，有的已清理；数字是早期 v0.1 时测的。

# oddcut：odd 风格自动剪辑最小原型

素材文件夹 + 一首音乐 → 卡点快切、首尾呼应、3:4 调色的成片。

## 目录结构

```
odd_analysis/
├── README.md            本文件：技术说明
├── docs/                风格拆解.md、拍摄清单.md（由模板 JSON 生成）
├── code/                全部代码（pip install -e code）
│   ├── oddcut/          剪辑引擎：analyze / music / planner / render / stickers / drawn_reveal / sticker_stage / paths
│   ├── templates/       风格模板 template_odd_daily.json
│   └── tools/           make_test_assets / render_shooting_guide / sticker_demo / drawn_demo / analyze_rhythm
├── assets/              输入（非生成）
│   ├── public/          Mixkit 公开素材 clips/ music/ SOURCES.md
│   ├── test/            合成测试素材
│   ├── reference/       5 条参考视频的抽帧图
│   └── models/          YOLO 权重、YOLOE 文本向量缓存
└── output/              生成物
    ├── edits/           完整成片（*.mp4 + *.timeline.json + 抽帧图）
    ├── stickers/        贴纸单镜头 demo
    ├── drawn/           手绘单镜头 demo
    └── analysis/        调色对比等分析图
```

所有路径集中在 `code/oddcut/paths.py`，要换根目录可以设环境变量 `ODDCUT_ROOT`。

## 用法

```bash
# 首次：创建环境，并把 code/ 以可编辑方式装进去（之后在任何目录都能 python -m oddcut）
python -m venv .venv && .venv/Scripts/python -m pip install -e code
# 贴纸 / 手绘开场还需要：.venv/Scripts/python -m pip install -e "code[vision]"（CPU 版 torch 见下文）

# 生成合成测试素材（18 段片段 + 120/76 BPM 鼓点）
.venv/Scripts/python code/tools/make_test_assets.py

# 剪辑
.venv/Scripts/python -m oddcut --clips assets/test/clips --music assets/test/music/drums_120bpm.wav --out output/edits/test_120.mp4
```

常用参数：`--music-start 30`（手动指定从歌曲第几秒开始；默认自动挑最响亮、鼓点最完整的一段，会跳过没有鼓点的前奏）、`--duration 20`、`--seed 3`（换一种剪法）、`--template xxx.json`。
每次输出都会附带 `*.timeline.json`，记录每个镜头用了哪段素材的哪几秒。

## 流程

| 步骤 | 文件 | 做什么 |
|---|---|---|
| 1 素材分析 | `code/oddcut/analyze.py` | 4fps 抽帧：清晰度（3×3 分格取最清晰一格的拉普拉斯方差，浅景深也算清晰）、亮度、运动量、**手抖**（相位相关全局位移的加加速度）、色相直方图、主体位置；过滤模糊/抖动/过暗素材 |
| 2 音乐分析 | `code/oddcut/music.py` | librosa 节拍检测 → 自动选段 → 折叠倍频/半频到模板 BPM 区间 → 补偿 1 个分析帧延迟 → 慢歌（<100 BPM）加入半拍 → 剪辑点网格 |
| 3 时间轴 | `code/oddcut/planner.py` | 开头（1.2～2.4s）+ 主体快切（0.5～1.5s，中位 0.8s，每 6～9 镜插一个 1.6～3s 呼吸镜头）+ 结尾（1.8～3.2s），每个边界都吸附到节拍网格；**锚点素材**的前后两段做首尾呼应；主体镜头按"上一镜结尾 ↔ 下一镜开头"的颜色和主体位置相似度串联（匹配剪辑链） |
| 4 渲染 | `code/oddcut/render.py` | 每镜精确到帧：裁成 3:4 1080×1440 → 调色（对比度、暖色平衡、抬黑位、暗角、颗粒；或 `.cube` LUT）→ 拼接 → 配乐并淡出，结尾淡出到黑 |

模板参数都在 `code/templates/template_odd_daily.json` 里（时长、镜头时长范围、BPM 区间、调色），改 JSON 就能调整风格。

## 已验证

**真实素材**（15 段 Mixkit 公开视频 + 2 首曲子，见 `assets/public/SOURCES.md`）：
- `output/edits/mixkit_400.mp4`（143.6 BPM，自动从 52.96s 起）：15/15 个剪辑点落在计划帧；15 段素材各用一次
- `output/edits/mixkit_738.mp4`（95.7 BPM，自动从 39.66s 起，慢歌加入半拍）：16/16 个剪辑点落在计划帧
- 首尾呼应：400 版用东京夜晚街道（4451），738 版用东京步行街（4231），都是同一素材的前后两段
- 呼吸镜头：400 版是拉花，738 版是纸灯笼和东京夜街；加了亮度约束，不会再选到几乎全黑的黑猫特写

**合成素材**：

- 两种速度（120 / 76 BPM）各渲染一次：**15/15、16/16 个剪辑点都精确落在计划帧上**；拍点和真实鼓点的误差全部在半帧（17ms）以内
- 模糊、抖动素材被正确过滤；用真实手机画面（参考视频）验证过，抖动检测不会误杀正常的手持镜头
- 素材不足时才会重复使用，并且不会出现在相邻位置
- 18 秒成片约 22 秒渲染完（4 线程）

## 已知限制 / 下一步

- **没有内容理解**：锚点镜头和匹配剪辑只看颜色、清晰度、运动和主体位置，不知道画面里"是什么"。下一步接多模态模型给片段打标签（天空/手持物/动物/光影…），让开头结尾和呼吸镜头选得更准
- Mixkit 素材大多是 16:9 横屏 720p，裁成 3:4 后只剩中间 540×720，放大后偏软；真实使用时用手机竖拍素材就没有这个问题
- 76 BPM 这类慢歌会被识别成 152 BPM（两者都在模板区间内），对剪辑网格没有影响，但显示的 BPM 是倍速
- 默认调色是滤镜链近似，正式使用建议做一个 `.cube` LUT
- 贴纸（眼睛、涂鸦）、系统 UI 叠加、特殊转场还没做，见 `docs/风格拆解.md` 第 3 节

## 贴纸跟踪 demo（物体拟人）

验证风格里最有辨识度的那一层：杯子贴卡通眼睛、猫头上画 💢 / 红问号，贴纸要跟着物体动。代码在 `code/oddcut/stickers.py`（单镜头）和 `code/tools/sticker_demo.py`（5 条测试素材批量跑）。

```bash
# 依赖（CPU 版 torch）
.venv/Scripts/python -m pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision
.venv/Scripts/python -m pip install ultralytics opencv-python pillow

# 5 条测试素材
.venv/Scripts/python code/tools/sticker_demo.py

# 单条：rule = eyes | anger | question
.venv/Scripts/python -m oddcut.stickers --clip assets/public/clips/808-720.mp4 --rule eyes --start 0 --dur 4 --out output/stickers/808_eyes.mp4
```

可选参数：`--anchor 0.5,0.82`（贴在物体的哪个位置，0～1）、`--size`、`--offset`、`--appear 0.15`（第几秒弹出，接主流程时可以对齐到拍点）。
权重第一次运行时会自动下载到 `assets/models/`：`yolo11s-seg.pt` 20MB、`yoloe-11s-seg.pt` 28MB。每遇到一个新的头部提示词（如 `dog head`），要先加载一次 600MB 的文本编码器 `mobileclip_blt.ts`，算出的向量缓存成 `yoloe_pe_*.pt`，之后就不用再加载。第一次用 YOLOE 时，ultralytics 会自动往 venv 里装一个 `clip` 包。

### 方案

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 物体 | YOLO11s-seg 逐帧检测（cup / cat 等 COCO 类别），先选置信度高、面积大的那个做种子，再按 IoU 往前、往后关联 | CPU 上约 85ms/帧，杯子和猫都很稳 |
| 眼睛贴哪 | 分割 mask 做形态学开运算，去掉把手、勺子这类细长部件，取"杯身"上 42% 高度处的中点和宽度 | 用检测框中心会被把手带偏 |
| 动物头 | YOLOE 开放词表检测 `"<类别> head"`，只认动物框里面的结果；锚点取头框**上沿**（💢 取右上角，? 取正上方） | COCO 没有"头"这个类别；OpenCV 5 的 pip 包里已经没有猫脸 Haar 级联了 |
| 跟踪 | 锚点附近取 LK 光流特征点，前后向一致性检查，再用 RANSAC 拟合相似变换 → 逐帧位移和缩放 | 帧间运动精确到亚像素，不会带上检测框的抖动 |
| 融合 | 贴纸位置 = 光流路径 + "检测 − 光流"的**鲁棒低通**（先用 2.4s 滑动中值找出离群点，再做 σ=0.4s 的零相位高斯）；大小也一样处理，但缩放的变化只交给光流 | 光流负责短期运动，检测负责消除长期漂移；检测连续错半秒也能当成离群点剔掉 |
| 摆放 | 头顶放不下时（头碰到画面上沿），整个镜头统一改放到侧边；锚点出画就缩小消失，回来再弹出 | 避免贴纸被硬压在画面边缘 |
| 绘制 | PIL 3 倍超采样手绘：眼睛有眨眼和左右扫视，💢 会一跳一跳，? 会左右摇；涂鸦每 3 帧重画一次抖动线条（手绘动画常见的"线条抖动"效果）；全部有弹出回弹 | 不依赖外部素材 |

没选 SAM2：没在本机实测，CPU 上做视频分割偏重，还需要点选提示，更适合以后做"抠图白描边贴纸"。也没选 CSRT/KCF 这类单目标 tracker：它们只给一个框，不知道头在哪，猫这种会变形的物体跟久了容易漂。

### 效果（`output/stickers/`）

每条输出 `*.mp4`，以及 `*_sheet.jpg`（干净抽帧）、`*_debug.jpg`（绿框是物体，蓝框是头，黄点是被采纳的检测，灰点是剔掉的离群检测，红十字是融合后的锚点）、`*_track.png`（检测、纯光流、融合三条轨迹对比）、`*_lock.jpg`（运动最快的 8 帧，以贴纸为中心裁切：物体在裁切框里不动，就说明贴纸粘住了）、`*.track.json`，汇总写在 `summary.json`。

|---|---|---|---|---|
| `32469_anger` 4.0s | 橘猫低头嗅石头 | 64% / 57% | 31 → 0.36 | 💢 一直在猫的右上方；1.0～1.6s YOLOE 把"头"框到了背上，被当成离群点剔掉 |

### 失败案例 / 限制

1. **YOLOE 的"猫头"框不可靠**：猫低头背对镜头时会框到背上（32469 有 43% 的检测被剔掉）；特写时会在"整个头"和"眼睛那一片"两种框之间来回跳，一跳就是好几秒（1778）。所以锚点才取头框上沿，并且让光流负责相对运动。如果检测错误持续超过约 1 秒、又占了多数，融合也纠正不过来。
2. **贴纸大小**：1778 的两种头框大小差 1.8 倍，现在只交给光流处理缩放，检测只管很慢的整体水平，但后半段还是缩小了约 30%。
3. **默认锚点不适合所有物体**：810 是俯拍杯子，默认的 42% 高度会落在咖啡液面上，正好在奶柱底下，要手动改到外壁。"贴哪儿"最终应该由规划器或多模态模型来决定，这也是 `docs/风格拆解.md` 里说的"多模态模型决定贴什么、贴哪儿"。
4. **没有遮挡**：贴纸永远画在最上层，手或奶柱从物体前面经过时会被贴纸盖住。要做遮挡，得用分割 mask 把前景重新画在贴纸上面。
5. **只跟一个目标**：画面里有多只猫时，只跟最有把握、面积最大的那只；出画后再入画按 IoU 重新关联，没有做外观重识别。
6. **贴纸是平的**：不会跟着物体旋转，也没有透视。光流的相似变换里其实已经有旋转角，以后可以直接用上。

### 怎么接进主流程

位置在 planner 选好镜头之后、render 之前，不需要改现有的调色和拼接逻辑：

1. **打标签**（analyze 阶段）：每段素材抽几帧跑一次 YOLO，记下有哪些可贴的类别（cup、cat、dog…）和大致位置，存进 `ClipAnalysis`。
2. **选镜头**（planner）：给 `Shot` 加一个可选的 `sticker` 字段（如 `{"rule": "eyes", "anchor": [0.5, 0.82]}`）。优先给开头、呼吸镜头和 ≥1s 的主体镜头加（贴纸弹出要 0.3s，观众还要时间看清）。每 4～6 个镜头最多加 1 个，也可以在模板 JSON 里配置；`appear` 对齐到镜头内的第一个拍点。
3. **渲染**（render）：对带 `sticker` 的镜头，先调用 `stickers.run(clip, rule, tmp.mp4, start=shot.src_start, dur=shot.frames/fps + 0.2)`，在源分辨率上生成一段已经贴好的中间片段，再把 `_render_shot` 的输入换成这个文件（`src_start=0`），后面的 3:4 裁切、调色、拼接都不用变。
4. **还要补的两点**：
   - 3:4 中心裁切会切掉 16:9 素材的两边，所以要把裁切窗口传给 `sticker_centers` 做限位，否则贴纸可能落在被裁掉的区域。
   - 现在贴纸会和画面一起被调成暗调暖色。如果希望白眼睛、红涂鸦保持原色，可以改成输出带透明通道的贴纸图层，在调色之后再用 ffmpeg `overlay` 叠上去。

### 已接入主流程

开着 `code/templates/template_odd_daily.json` 的 `stickers.enabled` 时，`python -m oddcut` 会自动加贴纸（用 `--no-stickers` 关掉；没装 ultralytics 会自动跳过）：

1. **打标签**（`code/oddcut/sticker_stage.py`）：每段素材每秒抽 1 帧跑 YOLO，只统计 3:4 裁切后仍在画面里的对象（动物至少 85% 在画面内，头顶才有地方放涂鸦；物体至少 60%）
2. **规划**（`planner.py`）：每 2～4 个镜头留一个 1.2～2.0s 的 `sticker` 镜头（模板 `body.sticker_shot`），每条最多 4 个；只从整个窗口都能看到可贴对象的素材里选，眼睛和涂鸦交替，不用最近 3 个镜头里出现过的素材
3. **渲染**（`render.py`）：贴纸镜头先裁成 3:4 再跟踪、画贴纸，生成中间片段，之后照常调色和拼接；目标没找到时退回成普通镜头

示例：`output/edits/odd_sticker_demo.mp4`（400 号曲子，3 个贴纸：咖啡杯眼睛、滤杯眼睛、橘猫 💢），13/13 个剪辑点落在计划帧上，总耗时约 85s（其中贴纸约 50s）。
贴纸目前也会被一起调色；猫的 💢 偶尔贴在背上而不是头顶（YOLOE 头部检测的已知问题，见上面的失败案例 1）。

## 手绘具象化 demo（单镜头）

针对"单一、正面朝向镜头"的主体（正脸的猫、一只杯子）：先在纸上一笔一笔画出线稿，再用马克笔/蜡笔上色成一张完整的卡通画，最后卡通画溶解成底下的真实画面。代码在 `code/oddcut/drawn_reveal.py`（单镜头 + 可画性判断 `is_drawable`）和 `code/tools/drawn_demo.py`（渲染、拒绝用例、全素材扫描）。

```bash
# 测试素材：渲染 + 拒绝用例 + 15 条素材的可画性扫描
.venv/Scripts/python code/tools/drawn_demo.py            # 也可以只跑 render / check / scan

# 单条（不合格的镜头默认不渲染，加 --force 强行渲染）
.venv/Scripts/python -m oddcut.drawn_reveal --clip assets/public/clips/22732-720.mp4 --start 0.25 --out output/drawn/22732_cat.mp4
```

可选参数：`--line 0.6` `--color 0.5` `--reveal 0.4`（三个阶段的时长）、`--tail 0.6`（具象化之后正常播放多久）、`--reveal-at 1.5`（"露出实拍"那一刻在片段里的秒数，用来对齐拍点）、`--colors 4`（上色用几种颜色）、`--native`（按裁切后的原始分辨率输出；默认画成 1080×1440，和主流程成片一致）。
依赖和模型同贴纸 demo（YOLO11s-seg + YOLOE）。新增了两个 YOLOE 提示词 `cat eye`、`cat nose`，向量已经缓存在 `assets/models/yoloe_pe_*.pt`；换成狗等其他动物时，第一次运行会加载一次 600MB 的文本编码器。

### 方案

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 裁切 | 先按主流程裁成 3:4（复用 `sticker_stage._center_crop_box`），检测在原分辨率（540×720）上做；画面画在 1080×1440 上，实拍用 Lanczos 放大 | 线条在成片分辨率上画，不会被放大糊掉 |
| 主体 | YOLO11s-seg 取面积最大的动物/物体 mask，用类别无关 NMS，再去掉和它重叠一半以上的检测 | 同一个杯子常被同时认成 cup 和 bowl，不能算成两个主体 |
| 物体的镂空 | mask 里颜色更接近 mask 外背景、又被主体整个包住、边缘清晰的块挖掉 | YOLO 的 mask 会把杯把手里的背景也填上。只看颜色的话，杯身上被灯照亮、和背后墙一样灰的那一条也会被挖掉；它的边缘是柔和的明暗过渡（梯度中位数 7），把手洞是清晰的轮廓（34，外轮廓 74），按 0.25×外轮廓梯度来区分 |
| 动物取半身 | YOLOE `"<类别> head / eye / nose"`；只画头框左右各放宽 6%、下巴往下 0.2 个头高的范围，范围边上不描线，颜色在这里做蜡笔式的渐隐 | 整只猫的 mask 占画面 57%，还包着草丛里看不清的身体和前景的草；画半身更像一张肖像速写 |
| 外轮廓 | `findContours`（RETR_CCOMP，把手的洞单独一笔）→ 环形高斯平滑 → 在拐角（耳尖、把手接口）处断成 3～4 笔，每笔约占周长 22～45%，相邻两笔略有重叠；碰到画面边缘的部分不描；从最上面开始画（动物先画耳朵），之后接离笔尖最近的一笔 | 人画轮廓也是几笔连起来的，不是一圈画完 |
| 内部线条 | 双边滤波 + 高斯模糊 → Canny（阈值取主体内梯度的 92 分位）→ 把边缘像素串成路径，在分叉处断开 → 去掉短的、贴着外轮廓的（mask 腐蚀 13px）、失焦的（沿线 \|Laplacian\| 不到主体典型边缘的一半），动物只保留头框里的 → 按"长度 × 强度"挑，总长不超过 0.9～1.2 倍周长，最多 40 笔 | 失焦过滤专门去掉挡在猫脸前的草叶：草叶的清晰度是 22～35，猫的毛纹和胡须是 54～200 |
| 五官（动物） | 眼睛：YOLOE 眼睛框 → 椭圆笔画；上色时填虹膜（框内中位色）、瞳孔（最暗的 22% 像素拟合椭圆）和高光点。鼻子：圆角倒三角，填框内的颜色。嘴：人中加"ω"。猫再加左右各 3 根胡须。五官附近不再取 Canny 线 | 只靠 Canny 的话，眼睛和嘴都是碎线，认不出是脸；用模板形状、按检测框摆位置，画出来就是卡通猫 |
| 笔触 | 每个点单独算宽度（压力噪声 + 两头细中间粗），整笔有一层固定的低频抖动（0.16% 画宽）；每 3 帧重画一次细微抖动（线条抖动效果，0.11%）；笔还在走的时候，笔尖不收细；描线进度按所有笔画的总长度走 ease-out（`1-(1-x)^1.35`） | 参考 `stickers._stroke`；指数取 1.35 是试出来的：取 2.4 时外轮廓 3 帧就画完，后面 0.3s 几乎不动 |
| 上色 | 半分辨率 mean-shift → Lab 空间 k-means（k=4，距离太近的颜色合并）→ 和背景颜色接近的簇（ΔE<14 且占比<30%）去掉，由周围的颜色补上 → 众数滤波 → 太小的块并进邻居 → 每个连通块是一个色块。颜色：提亮暗部（L→88+0.66L）、色度 ×1.45。从大块到小块错开填，每块用锯齿状推进的笔触扫满（方向在 25°～65° 之间随机）；纹理是斜向的马克笔条纹（亮度 ±6%）加上蜡笔在纸纹上留下的短斜空隙；眼睛和鼻子最后填 | 去掉背景色的簇，就不会把挡在猫前面的草画成绿色色块 |
| 具象化 | 实拍定格在起始帧。主体按"0.55 噪声 + 0.45 离主体中心的距离"溶解（这一阶段的前 60%），背景按"0.35 噪声 + 0.65 离主体的距离"从主体往外溶解（25%～90%），线条在 55%～100% 淡出；之后从定格帧接着正常播放 | 主体先实、背景后实、线条最后消失；从定格帧往后播，没有跳帧 |
| 时间 | 默认线稿 0.6 + 上色 0.5 + 具象化 0.4 + 正常播放 0.6 = 2.1s。`reveal_at` 比"线稿 + 上色"晚：画完的卡通先停住（线条继续抖动）等拍点；比它早：线稿和上色按比例压缩 | 把"露出实拍"那一刻对齐到拍点 |

### 可画性判断 `is_drawable(frames, fps)`

输入：从特效起点开始约 0.4s 的帧（已经裁成 3:4）。返回 `(是否合格, 原因, 测量值)`，原因写的是第一项没通过的检查：

1. 检测到动物或可正面拍的物体，置信度 ≥ 0.5
2. 单一主体：最大的 mask 至少是第二大的 3 倍（同一个物体被认成两个类别时只算一个）
3. 动物：YOLOE 头框置信度 ≥ 0.25，在身体框里面，面积不到身体框的 80%；头里有一对**水平的眼睛**（|dy| < 0.3·dx，眼距是头宽的 15%～75%，两只眼睛大小差不到 2 倍）；**鼻子**在两眼之间、眼睛下方；头没有被画面边缘裁掉。物体：外轮廓在画面边缘上的部分不超过 10%（808 的杯口右沿有 6% 碰到边）
4. 面积占画面 15%～60%（动物按画出来的半身算）
5. 起始帧清晰：主体轮廓一圈 9px 带内的 Laplacian 方差 ≥ 40（校准：猫 78，模糊 1px 后是 16；杯子 707 → 115 → 20）
6. 稳定：起始帧和 0.3s 后的主体 mask IoU ≥ 0.85

### 失败案例 / 限制

1. **没有正脸的动物画不像**（`32469_forced`）：低头的猫找不到头，只能画整只猫的剪影加几笔毛，像一团橘色的东西，看不出是猫。所以动物必须检测到"头 + 一对水平的眼睛 + 鼻子"；五官才是认出"这是一只猫"的关键
2. **置信度低的物体 mask 也不可靠**（`816_forced`）：玻璃滤杯被认成 cup（0.41），mask 连到了下面的分享壶支架，画出来底部是一块奇怪的台阶；玻璃又是透明的。因此加了置信度 ≥ 0.5 这一条（猫 0.59、杯子 0.93）
3. **颜色是光影，不是固有色**：k-means 分出来的是明暗。杯子被画成"暗的左半边 + 亮的右半边"，不是一只灰绿色的杯子；猫耳朵和额头的阴影变成了像三花猫一样的色斑。可以改成先做光照归一化再聚类，或者让多模态模型给出"这是什么颜色的杯子"
4. **半身的侧边是一条直线**：猫的 mask 往右连着失焦的身体，所以按头框宽度切掉。那一侧不描线，颜色也做了渐隐，但上色完成的那一帧右边还是能看出一条竖直的边
5. **五官是模板**：椭圆眼睛、三角鼻子、ω 嘴、胡须是按猫设计的，靠 YOLOE 框来摆位置。狗要换模板（不要胡须，嘴型不同）；鸟、人目前没有
6. **物体的"正面"其实没检查**：现在只要求完整、置信度够、不被裁掉。俯拍的杯子如果完整地在画面里，也会通过（810 是因为被裁掉才被拒的）
7. **镂空依赖颜色差**：只有把手洞里的背景和杯子颜色明显不同、边缘清晰时才挖得掉；浅色杯子放在浅色背景前可能挖不掉
8. **画面里只有一个主体时才合格**：这本来就是这个特效的定位；多主体的镜头（两只猫、杯子加碗）一律拒绝

### 怎么接进主流程

参照"贴纸跟踪 demo / 已接入主流程"两节，同样是在 planner 选好镜头之后、render 之前生成中间片段，不改调色和拼接：

1. **打标签**（analyze 阶段，放在 `sticker_stage.tag_clips` 之后）：只对已经标出动物或物体的素材，每 0.5～1s 取一个起点，用 `load_shot(..., out_height=None)` 读 0.4s，跑 `is_drawable`（约 0.5s 一次）。把合格的起点记进 `ClipAnalysis`，如 `clip.drawable = [(t, label, area)]`
2. **规划**（planner）：给 `Shot` 加一个可选字段 `drawn = {"src_start": t, "reveal_at": x}`。每条成片最多留 **1 个**约 2s 的特效镜头位（线稿 0.6 + 上色 0.5 + 具象化 0.4 + 播放 ≥0.5）。最好放在**开头**（画完再"变真"，正好当开场），其次放在呼吸镜头。`reveal_at` 取镜头内 ≥1.0s 的第一个强拍，让实拍在拍点上出现；`tail` 用来把片段补到下一个剪辑点。模板里加 `drawn.enabled`、`drawn.max_per_edit`、`drawn.slots: ["opening", "breath"]` 和三个阶段的时长
3. **渲染**（render）：对带 `drawn` 的镜头，先调用 `drawn_reveal.run(clip, src_start, tmp.mp4, Timing(reveal_at=..., tail=...), check=False)`，得到已经裁成 3:4 的 1080×1440 中间片段，再把 `_render_shot` 的输入换成这个文件（`src_start=0`）。render 里的裁切和缩放对它不起作用，后面照常调色、拼接。生成时如果找不到主体，就退回成普通镜头
4. **注意**：
   - 定格期间（约 1.5s）不消耗素材，实际只用到起点之后 `tail` 秒的素材，planner 计算素材窗口时要按这个算
   - 纸张和卡通色块也会被一起调成暖色暗调（还没在成片里验证过效果）；如果想让纸保持白色，可以只对具象化之后的部分调色，或者在调色之后再叠线稿层

### 手绘开场已接入主流程

开着模板里的 `drawn_opening.enabled` 时，`python -m oddcut` 会尝试用手绘画像做开场（用 `--no-drawn` 关掉）：

1. **扫描**（`sticker_stage.tag_drawable`）：只在已经标出动物或物体的素材里，每 1s 取一个起点跑 `is_drawable`，每段素材最多记 2 个合格起点（Mixkit 15 段素材约 40～50s，找到 4 个：草丛的猫，咖啡杯 ×2，滤杯）
2. **规划**（`planner._plan_drawn_opening / _choose_drawn`）：开场镜头的"露出实拍"落在 1.0～1.7s 窗口里最强的拍点上（`drawn_opening.reveal_window`），之后溶解 0.4s，再播放 0.5～1.1s 后切走；优先选动物，其次选面积大的主体。**结尾取同一段素材靠后的窗口**：开场画出来的猫，结尾以真实的样子再出现一次，做首尾呼应
3. **渲染**：调用 `drawn_reveal.run(..., check=True)` 生成中间片段，生成失败就退回普通开场

示例：`output/edits/odd_full_demo.mp4`（17.8s）：0～1.25s 手绘猫（线稿 → 上色），1.25s（强拍）开始露出实拍，2.48s 切走；中间 3 个贴纸（橘猫 💢、滤杯眼睛、倒奶杯眼睛），结尾回到同一只猫。11/11 个剪辑点落在计划帧上，总耗时约 160s。

接入时顺手修的问题：
- **色彩标记统一**：贴纸和手绘生成的中间片段没有色彩标记，相机素材标的是 bt709，混在一起拼接后，ffmpeg 抽帧时会重建滤镜、丢掉帧。现在每个镜头渲染时都统一加 `setparams` 并输出 bt709 标记
- **头部尺寸上限**：3:4 窄画面里 YOLOE 的猫头框可能接近整个画面宽，导致 💢 被判为"贴近边缘"而整段隐藏；头部尺寸按画面短边的 45% 封顶（只对涂鸦生效）
- **贴纸画完后检查**：可见时间不到一半，或者眼睛小于画面宽度的 15%，眼睛先换到杯壁位置（锚点 0.5,0.8）重试，还不行就退回普通镜头
- **同一段素材最多一个贴纸**

### 中段手绘镜头 + 不重复开场的结尾

模板里新增两个开关（`code/templates/template_odd_daily.json`）：

- `drawn_mid`：在 `after_seconds`（默认 4s）之后的第一个呼吸镜头位置，再放一个手绘镜头，优先选物体（`prefer_family: "object"`），不能和开场用同一段素材。两个手绘镜头的素材都会预先留出，不再被普通镜头或贴纸镜头使用
- `drawn_opening.loop_outro`：`true` 时结尾取开场素材靠后的一段（首尾呼应）；`false`（当前默认）时结尾从剩下的素材里挑一个稳定、明亮的镜头，开场的主体不会在最后出现
- 选手绘素材时，检测置信度也计入评分（`1.0 × conf + 0.5 × 面积`），避免选到玻璃滤杯这类低置信度主体（滤杯约 0.5，马克杯 0.93）

示例：`output/edits/odd_full_demo_v2.mp4`（18.2s）：0～2.5s 手绘猫开场 → 3 个贴纸（橘猫 💢、滤杯眼睛、倒奶杯眼睛）→ 13.3s 手绘咖啡杯（1.23s 后在拍点上露出实拍）→ 15.7s 起东京街头淡出收尾。11/11 个剪辑点落在计划帧上，耗时约 160s。

### 只画主体、背景保留实拍（`background: "real"`，当前默认）

`drawn_reveal.render(..., background="real")`：不再把整个画面换成纸张，而是只在主体区域手绘，其余部分一直是真实画面。

- **擦除主体**（`clean_plate`）：把起始帧里整个主体区域（检测 mask ∪ 手绘区域，稍微外扩）从画面中去掉，用周围背景做多尺度归一化卷积补上，就像场景里原本没有这只猫或这个杯子。在 1/4 分辨率下计算，再羽化边缘贴回去
- 线稿、填色都画在这张"擦掉主体的实拍"上；露出实拍时，主体区域先溶解回真实画面，被擦掉的其余部分（比如猫身）随背景一起回来
- 模板 `drawn_opening.background` 可选 `"real"` 或 `"paper"`（原来的整张纸效果），单镜头命令行用 `--background`
- 示例：`output/drawn/real_bg/`（猫、杯子单镜头）、`output/edits/odd_full_demo_v3.mp4`（完整成片，11/11 个剪辑点落在计划帧上）
- 已知问题：补出来的区域是平滑的色块（草地变成一片均匀的绿），线稿阶段能看出来；画面边缘紧贴主体的颜色会被带进补出来的区域（猫左侧的一点橘色）
